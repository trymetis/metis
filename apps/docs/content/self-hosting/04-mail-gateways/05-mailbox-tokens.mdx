---
title: Mailbox tokens
description: Create, list and revoke the per-address tokens people use to connect gateway mailboxes, and set the sender name each address sends with.
---

Each address on a gateway has its own mailbox token. The token lets one person read and send mail for that address only. You create tokens with the gateway's admin token, then give each token to the person who owns the address.

Each address can also have a sender name, such as "Alice Doe". This is the name people see next to the address when they get mail from it. See [Sender name](#sender-name).

## With the metis CLI

`metis gateway token` creates, lists and revokes tokens on the gateway that serves an address. It also sets each address's sender name.

### On the server

On a server the `metis` CLI runs, the CLI finds the gateway from the address's domain, and uses the admin token it keeps:

```bash
sudo metis gateway token create alice@example.com
```

It prints "Token for alice@example.com (shown once; paste it when connecting the mailbox):" and the token on the next line. Copy it and send it to the person in a safe way. Creating a token again for the same address replaces the old one, so the old token stops working.

To give the address a sender name at the same time, add `--name`:

```bash
sudo metis gateway token create alice@example.com --name "Alice Doe"
```

To list and revoke tokens:

```bash
sudo metis gateway token list example.com
sudo metis gateway token revoke alice@example.com
```

- `list` takes the domain or an address on it, which picks the gateway. It prints one line of JSON for each address that has a token, sorted by address. Each line has the address (`address`), its sender name (`name`, or `null` when it has none) and when its first token was created (`created_at`).
- `revoke` stops the token for an address at once, and prints "Revoked the token for alice@example.com".

If no gateway on the server serves the domain, the command says, for example, "No gateway on this server serves example.org."

### From your computer

For a gateway that is not on a server the `metis` CLI runs, pass the gateway's address and its admin token (the `API_TOKEN` you set or were shown when you deployed it):

```bash
metis gateway token create alice@example.com --endpoint https://resend-gateway.example.com --admin-token your-admin-token
```

`list`, `name` and `revoke` take the same two flags. Without them, the command says "Away from the server, pass `--endpoint` and `--admin-token`."

## Sender name

A sender name is the name that goes with an address on the mail it sends. With the name "Alice Doe", people who get mail from `alice@example.com` see it as from Alice Doe, with the address next to the name. The copy in the Sent folder shows the name too, so Metis Suite shows it as the sender. Drafts saved for the address carry the current name.

An address with no sender name sends from the bare address.

### Set or change the name

Set the name when you create the token, with `--name` (see above). To set or change it later, use `name`. The address keeps its token, and the token keeps working, so the person does not need to connect again:

```bash
sudo metis gateway token name alice@example.com "Alice Doe"
```

It prints "alice@example.com sends as Alice Doe".

From your computer, add the gateway's address and admin token:

```bash
metis gateway token name alice@example.com "Alice Doe" --endpoint https://resend-gateway.example.com --admin-token your-admin-token
```

### Remove the name

Give an empty name:

```bash
sudo metis gateway token name alice@example.com ""
```

It prints "alice@example.com sends with no name".

### What to know

- **The name follows these rules:** spaces at the start and end are removed, and a name that is left empty means no name. It can be at most 100 characters, on one line, with no line breaks or tabs. Commas, quotes and other punctuation are fine.
- **Creating a token again keeps the name.** Without `--name`, a new token for the address keeps the name it already has. With `--name`, the new name replaces it. `--name ""` does not remove a name: to remove it, see [Remove the name](#remove-the-name).
- **Revoking the token removes the name.** If you create a token for the address again, set the name again.
- **A new name applies only to mail sent after the change.** Each message keeps the name it was sent with.
- **Only you set the name.** It needs the gateway's admin token. There is no setting for it in Metis Suite, and the person who uses the mailbox cannot change it.
- **The gateway must run a release that has sender names.** An older gateway creates the token but ignores the name, and answers "Method not allowed" to `name`.

To move a gateway to a new release, see [Cloudflare Email](/self-hosting/mail-gateways/cloudflare-email), [Resend](/self-hosting/mail-gateways/resend) or [Amazon SES](/self-hosting/mail-gateways/amazon-ses). If you run the Resend gateway with Bun, or deployed the Cloudflare Email or Amazon SES gateway by hand, run `bun run db:apply` from the new release before you start or deploy it, as each page explains. Update the `metis` CLI too, with `sudo metis self-update`.

## With Bun, from the source code

You can also run the token commands from the gateway's folder in the source code: `apps/gateway-cloudflare`, `apps/gateway-resend` or `apps/gateway-ses`. Each command needs the gateway's admin token and the gateway's address:

| Gateway          | Example address                                                        |
| ---------------- | ---------------------------------------------------------------------- |
| Cloudflare Email | `https://metis-cf-mail.you.workers.dev`                                |
| Resend           | `https://resend-gateway.example.com`                                   |
| Amazon SES       | `https://abcdefghijklmnopqrstuvwxyz012345.lambda-url.us-east-1.on.aws` |

To create a token for `alice@example.com` on a Resend gateway, run:

```bash
ADMIN_TOKEN=your-admin-token bun run token https://resend-gateway.example.com create alice@example.com
```

Put your admin token in place of `your-admin-token`, and your gateway's address in place of the example address. The token is printed once.

To give the address a sender name at the same time, add the name after the address. Without it, the address keeps the name it already has:

```bash
ADMIN_TOKEN=your-admin-token bun run token https://resend-gateway.example.com create alice@example.com "Alice Doe"
```

To set or change the sender name later, without a new token:

```bash
ADMIN_TOKEN=your-admin-token bun run token https://resend-gateway.example.com name alice@example.com "Alice Doe"
```

It prints "alice@example.com sends as Alice Doe". To remove the name, give `""` as the name. It then prints "alice@example.com sends with no name".

To list and revoke tokens:

```bash
ADMIN_TOKEN=your-admin-token bun run token https://resend-gateway.example.com list
ADMIN_TOKEN=your-admin-token bun run token https://resend-gateway.example.com revoke alice@example.com
```

## What list and revoke show

`list` shows which addresses have a token, the sender name of each, and when the first token for each address was created. Creating a new token for an address does not change this date. `revoke` stops the token for an address at once, and removes its sender name.

If a command fails, it prints the reason. With the `metis` CLI, the reason follows the gateway's address and status, for example "https://resend-gateway.example.com/v1/tokens answered 400: The name must be one line of at most 100 characters." With Bun, the reason follows the status, for example "404: No token exists for alice@example.com".

- "The address must be on @example.com": the address is not on the gateway's domain.
- "Unauthorized": the admin token is wrong.
- "Token management needs the admin API_TOKEN": you used a mailbox token instead of the admin token.
- "Create needs an address such as alice@example.com.": with the `metis` CLI, `create` takes a full address, not a domain.
- "The name must be one line of at most 100 characters": the sender name is too long, or it has a line break or a tab. With `create`, no token is created. Fix the name and run the command again.
- "No token exists for alice@example.com": `name` works only for an address that has a token. Create a token first.

:::warning
With the Resend and Amazon SES gateways, an address with no token does not receive mail. The Resend gateway drops mail sent to it, and the Amazon SES gateway deletes it from the bucket. Revoking an address's token stops its mail. With the Amazon SES gateway, mail the address already received is kept, and it appears again if you create a new token for that address. With the Cloudflare gateway in catch-all mode, mail for an address with no token is kept until you create one.
:::

## What the person does

The person connects a new mailbox, picks your gateway by its name, and enters:

- **Email address**: the address the token was created for.
- **Mailbox token**: the token you gave them.

Metis Suite refuses the gateway's admin token in this field, and a token shorter than 16 characters. It also checks that the token belongs to the address entered. For the user side, see [Mail](/guide/mail).

Mail they send carries the sender name you set for the address. They cannot change it in Metis Suite, so they ask you when it needs to change.
