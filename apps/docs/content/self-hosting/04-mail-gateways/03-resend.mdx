---
title: Set up the Resend gateway
description: Run a gateway that receives mail through Resend, keeps it in your own database, and sends through Resend.
---

The Resend gateway is a small service you run for one domain. It receives mail through Resend's inbound webhook and sends through Resend. It stores messages in a libSQL database. libSQL is an open-source database built on SQLite. It keeps raw mail and attachments in a folder or in S3-compatible storage. Resend deletes received mail after 30 days, so the gateway keeps its own permanent copy.

Mail for an address with no mailbox token is dropped. Creating a token for an address is what turns it on.

Search in a Resend gateway mailbox ignores upper and lower case only for the letters A to Z. For other letters, such as accented ones, the case must match.

You can set it up with the `metis` CLI, or by hand.

## Set it up with the metis CLI

### Before you start

- A Resend account and an API key with full access.
- A domain you control, such as `example.com`. If it already has MX records for another mail service, use a subdomain.
- On a server the `metis` CLI runs, a domain for the instance itself. The gateway needs a public HTTPS address for Resend's webhook. See [Domain and HTTPS](/self-hosting/install/domain-and-https).

### On the server

On a server the `metis` CLI runs, pass the Resend key on the same line:

```bash
sudo RESEND_API_KEY=your-resend-api-key metis add gateway-resend --domain example.com
```

Without `RESEND_API_KEY`, the command asks for the **Resend API key**: "A key with full access. Set RESEND_API_KEY to skip this question." The gateway keeps the key, so a later run of the same command reuses it.

The command:

1. Adds the domain to Resend, or finds it there: "Resend domain example.com".
2. Creates the DNS records Resend needs, and an A record for the gateway's address that points at the server. With `CLOUDFLARE_API_TOKEN` set and the domain on that Cloudflare account, it creates them there. Otherwise it prints them under "Add these DNS records at your DNS provider:". Add them at your DNS provider.
3. Asks Resend to check the domain: "Waiting for Resend to verify example.com (up to 10 minutes)…", then "Resend verified example.com". If it takes longer, the command lists each record with its status and says "Run the same command again once DNS has spread". Running it again continues where it stopped.
4. Creates Resend's webhook: "Resend webhook to https://resend.mail.example.com/webhooks/resend".
5. Starts the gateway on the server, served by Caddy on `resend.` followed by your instance's domain, such as `resend.mail.example.com`. It also checks Resend for missed mail every 5 minutes.
6. Waits until it answers: "Waiting for https://resend.mail.example.com to answer (Caddy may first need a certificate)…", for up to 3 minutes.
7. Adds the gateway to the **Resend** server list, named after the domain, and stores it at once.

Then create a mailbox token for each address with `sudo metis gateway token create alice@example.com`. See [Mailbox tokens](/self-hosting/mail-gateways/mailbox-tokens).

| Flag         | What it does                                                                                                                                                                                                                   | Default                                      |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------- |
| `--domain`   | The mail domain.                                                                                                                                                                                                               | None                                         |
| `--host`     | The gateway's public address, such as `resend.mail.example.com`.                                                                                                                                                               | `resend.` followed by your instance's domain |
| `--database` | `own`: the gateway keeps its mail in its own database server. `stack`: it keeps it in the server's sqld, next to your instance's databases. With `stack`, **Undo last upgrade** also rolls back the gateway's mail and tokens. | `own`                                        |
| `--blobs`    | Where raw mail and attachments go. `dir`: a Docker volume. `objstore`: the server's object storage, in a bucket named `gateway-resend`. `objstore` needs `sudo metis add objstore` first.                                      | `dir`                                        |
| `--region`   | The Resend region: `us-east-1`, `eu-west-1`, `sa-east-1` or `ap-northeast-1`.                                                                                                                                                  | `us-east-1`                                  |
| `--version`  | The gateway release to run, such as `0.1.0`.                                                                                                                                                                                   | The newest release                           |
| `--yes`      | Go ahead without asking.                                                                                                                                                                                                       |                                              |

Mail gateways have their own releases, separate from Metis Suite releases. Any gateway release works with any Metis Suite release. Upgrading your instance never changes the gateway. To move the gateway to its newest release, run the same `metis add` command again. To stay on one release, pass `--version`, such as `--version 0.1.0`. A flag you leave out then goes back to its default.

`sudo metis status` shows the release the gateway runs. When a newer one is out, it says so, for example "example.com on https://resend.mail.example.com, 0.1.0, 0.2.0 is out: run metis add again to move it".

### With the gateway elsewhere

If your instance runs on a container platform or Vercel, run the gateway image there first (see [Run the gateway](#run-the-gateway)). Then, on your computer, let the CLI set up the Resend side:

```bash
RESEND_API_KEY=your-resend-api-key metis add gateway-resend --endpoint https://resend-gateway.example.com --domain example.com
```

`--endpoint` is the gateway's address. The command sets up the domain and the webhook as above, then prints "Set these on the gateway at https://resend-gateway.example.com:", followed by `MAIL_DOMAIN`, `API_TOKEN`, `RESEND_API_KEY` and `RESEND_WEBHOOK_SECRET` with their values. Set them on the gateway and restart it. It also prints the server entry, with "Add this server under Dashboard → System, or store it with `metis config set --env-file`:". Keep the `API_TOKEN`: you need it to create mailbox tokens.

### Remove it

```bash
sudo metis remove gateway-resend
```

It warns "Mailboxes connected through this gateway are quarantined when the app restarts." and asks "Go ahead?". It then deletes Resend's webhook ("Deleted the Resend webhook"), stops the gateway and removes the server entry. The domain stays in Resend. With `--purge`, it also deletes the gateway's mail and tokens: its Docker volumes with `--database own`, or its database on the server's sqld with `--database stack`.

For a gateway that runs elsewhere, run this on your computer:

```bash
RESEND_API_KEY=your-resend-api-key metis remove gateway-resend --domain example.com --endpoint https://resend-gateway.example.com
```

It deletes the webhooks to that address and prints, for example, "Deleted 1 Resend webhook(s) to https://resend-gateway.example.com". It ends with "Remove the server metis-resend-example-com from Dashboard → System, or drop it from METIS_RESEND_SERVERS." Stop the gateway yourself.

### If something goes wrong

| Message                                                                                                      | What to do                                                                                        |
| ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| "the Resend gateway needs a public HTTPS address for its webhook; run `metis domain mail.example.com` first" | Give the instance a domain first. See [Domain and HTTPS](/self-hosting/install/domain-and-https). |
| "`--database stack` needs the server's sqld"                                                                 | Your instance's databases are elsewhere. Use `--database own`.                                    |
| "`--blobs objstore` needs `metis add objstore` first"                                                        | Run `sudo metis add objstore` first, or use `--blobs dir`.                                        |
| "`--region` takes us-east-1, eu-west-1, sa-east-1, ap-northeast-1"                                           | Pick one of these regions.                                                                        |
| "Run the same command again once DNS has spread"                                                             | DNS changes take time to spread. Wait, then run the same command again.                           |
| "the Resend gateway is not on"                                                                               | There is no Resend gateway on this server.                                                        |

## Set it up by hand

### Before you start

- A Resend account with your domain verified and receiving turned on, including Resend's inbound MX record on the domain. If the domain already has MX records, use a subdomain.
- A Resend API key with full access. It stays inside the gateway.
- A libSQL database of its own, not one of your Metis Suite databases. It can be on a libSQL server (sqld), on Turso, or a local file. The gateway creates its tables itself.
- Docker, to run the published image. To run the gateway with Bun instead, see step 2.
- [Bun](https://bun.sh) and a copy of the Metis Suite source code, to create mailbox tokens (step 5) and to run the gateway from the source code:

```bash
git clone https://github.com/trymetis/metis.git
cd metis
bun install
cd apps/gateway-resend
```

### The gateway image

Each release of the Resend gateway publishes a ready-made image of it: `ghcr.io/trymetis/metis-gateway-resend`. It is public, so you need no sign-in to download it.

| Tag      | What it is                                                                            |
| -------- | ------------------------------------------------------------------------------------- |
| `0.1.0`  | Release 0.1.0 of the gateway.                                                         |
| `latest` | The newest release that is not a pre-release. A pre-release does not change `latest`. |

The gateway has its own releases, separate from Metis Suite releases. You can use any tag: any gateway release works with any Metis Suite release. To see the gateway's releases, open the **Resend gateway** tab of the [changelog](/changelog?platform=gateway-resend). `https://sh.trymetis.email/gateway-resend/version.txt` names the newest release that is not a pre-release.

Write the tag without the leading `v`: `0.1.0`, not `v0.1.0`.

### Run the gateway

<Steps>
  <Step title="Set its variables">
    Write the gateway's settings to a file named `.env`. With the published
    image, the file can be in any folder. When you build the image yourself
    or use Bun, put it in `apps/gateway-resend`.

    | Variable | Required | What it is |
    | --- | --- | --- |
    | `DATABASE_URL` | yes | The libSQL address of the database. It starts with `http://`, `https://`, `libsql://`, `ws://`, `wss://` or `file:`. For a local file, use for example `file:gateway.db`. |
    | `DATABASE_AUTH_TOKEN` | no | The database's token, when it needs one, such as for a Turso database. |
    | `MAIL_DOMAIN` | yes | The domain this gateway serves. |
    | `API_TOKEN` | yes | The admin token, for example from `openssl rand -hex 32`. |
    | `RESEND_API_KEY` | yes | Your full-access Resend key. |
    | `RESEND_WEBHOOK_SECRET` | yes, in practice | The webhook's signing secret (next step). Without it, the webhook refuses deliveries, and only the catch-up check (`POLL_INTERVAL_SEC`) receives mail. |
    | `PORT` | no | Default `8787`. |
    | `POLL_INTERVAL_SEC` | no | Seconds between catch-up checks for received mail. `0` (the default) turns them off. Useful when Resend cannot reach the webhook, and as a backstop. |
    | `BLOB_DIR` | no | The folder for raw mail and attachments when you use no S3-compatible storage. Default `data/blobs`, inside the folder the gateway runs in. In the Docker image, the default is `/data/blobs`. |
    | `BLOB_ENDPOINT`, `BLOB_BUCKET`, `BLOB_KEY_ID`, `BLOB_SECRET` | no | S3-compatible storage (such as R2 or S3) for raw mail and attachments. Set all four or none. With none, they are stored in `BLOB_DIR`. If you set only some of them, the gateway stops when it starts, with an error that says they must be set together. |
    | `BLOB_REGION` | no | Used only with S3-compatible storage. Default `auto`, which suits R2. |

  </Step>

  <Step title="Start it">
    Use one of these:

    - Docker, with the published image. Run this from the folder that holds
      your `.env` file. Use a gateway release, such as `0.1.0`, or `latest`.
      Each time the container starts, it creates any tables that are
      missing. Then it serves on port 8787.

      ```bash
      docker run -d --name metis-resend --env-file .env -p 8787:8787 \
        -v metis-resend-data:/data ghcr.io/trymetis/metis-gateway-resend:0.1.0
      ```

      The container keeps its files under `/data`. The named volume
      `metis-resend-data` keeps them when you recreate the container. If
      you use a local file as the database, put it under `/data` too, for
      example `DATABASE_URL=file:/data/gateway.db`, so it is kept as well.

    - Docker, with an image you build from the source code. Run this from
      the root of the source code (run `cd ../..` first if you are still in
      `apps/gateway-resend`):

      ```bash
      docker build -f apps/gateway-resend/Dockerfile -t metis-resend .
      docker run -d --name metis-resend --env-file apps/gateway-resend/.env -p 8787:8787 -v metis-resend-data:/data metis-resend
      ```

      It works like the published image.

    - Bun, from `apps/gateway-resend` in the source code. Create the tables
      first, then start it. You can run `bun run db:apply` again at any
      time. It keeps your data.

      ```bash
      bun run db:apply
      bun run start
      ```

    Serve it over `https://` on an address Resend and your Metis Suite
    instance can both reach.

  </Step>

<Step title="Add the webhook in Resend">
  In the Resend dashboard, add a webhook for the `email.received` event, pointing at
  `https://resend-gateway.example.com/webhooks/resend`. Copy its signing secret, which starts with
  `whsec_`, into `RESEND_WEBHOOK_SECRET`, and restart the gateway.
</Step>

  <Step title="Register it in Metis Suite">
    Open **Dashboard**, **System**, **Resend** under **Providers**. Click
    **Add server** and fill in:

    - **Name**: what users see in the connect dialog.
    - **Domain**: your domain, such as `example.com`.
    - **Gateway endpoint**: the gateway's `https://` address. Any other
      address is refused with "The gateway endpoint must be an https://
      URL".

    Click **Save changes** and enter your authenticator code.

    You can also set the starting list before the first start:

    ```bash
    METIS_RESEND_SERVERS=[{"name":"Example Mail","domain":"example.com","endpoint":"https://resend-gateway.example.com"}]
    ```

  </Step>

  <Step title="Create mailbox tokens">
    Create a token for each address. Until you do, mail for that address is
    dropped. See [Mailbox tokens](/self-hosting/mail-gateways/mailbox-tokens).
  </Step>
</Steps>
