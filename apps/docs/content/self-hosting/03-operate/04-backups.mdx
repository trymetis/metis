For a deployment on a container platform, Vercel or another Node host, the `metis` CLI on your computer can copy the whole instance into one encrypted file, and load it into new databases later. See [Export and import](/self-hosting/operate/export-and-import).

On a server the `metis` CLI runs, `sudo metis db export` makes the same encrypted file on the server, in `/opt/metis-suite/exports`. Copy it off the server, because it is lost with the server's disk, or let the CLI upload it to S3 with `--out s3://example-backups/metis`. See [Upload to S3](/self-hosting/operate/export-and-import#upload-to-s3). The owner sees every export, and where each archive went, under **Dashboard**, **System**, **Exports**. The file does not hold the files on **Server storage**, the files under `/opt/metis-suite/env/`, Caddy's HTTPS certificates or the messages the Resend gateway stores. Back those up with the tools you already use for Docker volumes and files on your server. See [On a server the metis CLI runs](/self-hosting/operate/export-and-import#on-a-server-the-metis-cli-runs).

On Metis Cloud, the Cloud service (not Metis Suite itself) backs up every running instance each night, keeps the two most recent backups and deletes them with the instance. The console has no button to restore them, so for a copy of your own, download one from the console. See [Export your data](/cloud/your-instance/export-your-data).

The updater keeps one copy of the database from before your last upgrade, so that you can undo it. That copy is not a backup. See [The upgrade snapshot is not a backup](#the-upgrade-snapshot-is-not-a-backup).

Most mail, events and files are not stored by Metis Suite at all. They stay with the provider or server each user connected, such as Gmail, Outlook or your IMAP server. Your instance keeps the accounts, the connections and their credentials, the settings, and what people create in the app.

Your instance also keeps a copy of the body of each message someone opened, until nobody has opened it for the number of days set on the **Mail cache** card (30 by default). It keeps the subjects, senders, AI labels, summaries and phishing check results of those messages too. See [Mail cache](/self-hosting/reference/dashboard-settings#mail-cache).

## What lives where

On a server the `metis` CLI runs, your data is in Docker volumes, and your settings and secrets are in the install folder, `/opt/metis-suite`.

### Docker volumes

| Volume                                      | What it holds                                                                                                                                                                                                                                                                                      |
| ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `metis-sqld`                                | The app database and the AI memory database: accounts, workspaces, connections, settings and their history, workflows, scheduled mail, the audit log, stored copies of opened message bodies, and the assistant's memory. With the Resend gateway on `--database stack`, also its mail and tokens. |
| `metis-caddy-data`, `metis-caddy-config`    | HTTPS certificates and Caddy's own state. Caddy gets a new certificate if these are lost, so they are optional.                                                                                                                                                                                    |
| `metis-objstore`                            | The files on **Server storage**, unless you chose a folder with `--data-dir`. Then back up that folder instead. With the Resend gateway on `--blobs objstore`, it also holds the gateway's mail, in the `gateway-resend` bucket.                                                                   |
| `metis-redis`                               | The workers' queue, which Redis keeps on disk.                                                                                                                                                                                                                                                     |
| `metis-sqld-resend`, `metis-gateway-resend` | The Resend gateway's own database and its stored mail, with `--database own` and `--blobs dir` (the defaults).                                                                                                                                                                                     |

You have only the volumes of the components you added. See [Manage components](/self-hosting/operate/manage-components).

### The install folder

| Path                          | What it holds                                                                                                                                   |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `/opt/metis-suite/.env`       | Every app secret, including the encryption key, the app secret, the database credentials and the setup code.                                    |
| `/opt/metis-suite/env/`       | The keys of the server's object storage and of the Resend gateway's database, each gateway's admin token (`API_TOKEN`), and the Resend API key. |
| `/opt/metis-suite/Caddyfile`  | Caddy's settings. The CLI writes it again on every change.                                                                                      |
| `/opt/metis-suite/snapshots/` | The upgrade snapshot (see below).                                                                                                               |
| `/opt/metis-suite/exports/`   | The encrypted exports `sudo metis db export` writes, unless it uploaded them to S3. Copy them off the server.                                   |

The folder also holds the CLI's record of which components are on, their options and the release you run. Back up the whole folder. `/etc/metis/install-dir` tells the CLI where the folder is.

If your databases are on Turso or another database server, they live there instead of in the `metis-sqld` volume. The updater then takes no snapshot, so back them up before every upgrade.

:::warning[The encryption key and the database belong together]
The passwords and tokens in the database can be read only with the `METIS_ENCRYPTION_KEY` that was in use when they were stored. A database backup without its key is not enough to bring connections back: every user would have to reconnect every mailbox, calendar, drive and address book. Keep a copy of `.env`, or at least the key, with every database backup, and store it somewhere other than the server.
:::

## The upgrade snapshot is not a backup

When your database is on the server's own database server, the updater copies it before each upgrade, from the dashboard or with `metis update`. It keeps that copy so that you can [undo the last upgrade](/self-hosting/operate/upgrade-and-undo#undo-the-last-upgrade).

Do not rely on it as a backup:

- There is only one. Each successful upgrade replaces it, and an undo uses it up.
- It sits on the same server as the database, so it is lost with the server.
- It holds the database only, not `.env` and its encryption key.
- `sudo metis update --no-backup` takes no snapshot, and removes the one kept for undo.
- It holds only the `metis-sqld` volume: not the Resend gateway's own database (`metis-sqld-resend`) or its mail.
- With Turso or your own database server, there is no snapshot at all.

The `/opt/metis-suite/snapshots/` folder holds a full copy of your database, so protect it as you protect the `metis-sqld` volume. It needs disk space: during an upgrade, the server can hold two copies at once. If you delete the folder, you lose the undo.

## Mailbox gateways

If you run a Cloudflare Email, Resend or Amazon SES gateway, it keeps its mail in its own storage, separate from your instance. Back it up there. For the Resend gateway, that is its libSQL database and its folder or S3-compatible storage. For the Amazon SES gateway, that is its libSQL database and its S3 bucket. See [Mail gateways](/self-hosting/mail-gateways).
