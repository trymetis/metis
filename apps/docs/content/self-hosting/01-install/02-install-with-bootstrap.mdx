---
title: Install with the metis CLI
description: Install Metis Suite on a Linux server with the metis CLI, then find the setup code for the owner account.
---

In this tutorial you install a complete Metis Suite instance on a Linux server. You use the `metis` CLI, a command-line tool that installs and runs Metis Suite. It installs Docker when the server has none, generates every secret, picks the newest release and starts everything. By the end, the app is running and you have the setup code that creates the owner account.

## What gets installed

These always run:

- **The app**: Metis Suite itself. It listens on `127.0.0.1:3000` only, so it is not reachable from the internet on its own.
- **Preflight**: a one-time check that runs before a new app starts. It applies the release's changes to the database and checks your settings.
- **sqld**: the database server, unless you choose another database. It holds the app database and the AI memory database, in the `metis-sqld` Docker volume.

These are optional. Each one is a component, a part you can add or remove at any time with `metis add` and `metis remove`:

- **Caddy**: serves the app over HTTPS. It comes with a domain.
- **The updater**: lets you upgrade from **Dashboard**, **System**, **Updates**, and undo the last upgrade. It is on by default.
- **Workers with Redis**: run background work outside the app.
- **Object storage**: a drive on your server.
- **Mail gateways**: mailboxes on your own domain, through Cloudflare Email, Resend or Amazon SES.

See [Manage components](/self-hosting/operate/manage-components).

Everything is installed in `/opt/metis-suite`. Your settings go in `/opt/metis-suite/.env`, which only root can read.

## Before you start

- A server that meets the [requirements](/self-hosting/install/requirements).
- **The owner email.** The owner is the account that always has full access to the owner dashboard, where you change settings and apply updates. Pick the email address you will sign in with, for example `alice@example.com`. Only this address can create the owner account on the setup page. Later, the owner can give other people access to the dashboard. See [Instance roles](/self-hosting/operate/owner-dashboard#instance-roles).
- **Your domain, if you have one,** such as `mail.example.com`. You can leave it out and add it later.

<Steps>
  <Step title="Download the install script">
    Sign in to the server and download the script:

    ```bash
    curl -fsSL https://sh.trymetis.email/bootstrap -o bootstrap.sh
    ```

  </Step>

  <Step title="Run it">
    ```bash
    sudo sh bootstrap.sh
    ```

    The script downloads the `metis` CLI for your server's processor,
    checks it against its published checksum, installs it as
    `/usr/local/bin/metis`, and starts `metis setup`. From then on, you run
    every command as `sudo metis` followed by the command.

  </Step>

  <Step title="Fill in the form">
    Setup asks a few questions. Each one is also a flag, so you can answer
    them on the command line instead (see
    [Install without questions](#install-without-questions)).

    - **Domain**: "The hostname people open, such as mail.example.com.
      Leave it blank to reach Metis only through an SSH tunnel for now."
      Write the name only, without `https://`.
    - **Owner email**: "The instance owner; the setup page accepts only
      this address."
    - **Database**: **sqld on this server** (the usual choice), or **A
      libSQL database elsewhere (Turso or your own sqld)**. See
      [Use Turso or your own database server](#use-turso-or-your-own-database-server).
    - **Components**: tick what you want now. **Updater: upgrade from
      Dashboard → Updates** is ticked already. The others are **Workers
      with Redis: run workflows outside the app**, **Object storage: a
      drive on this server**, and the three mail gateways. The Resend
      gateway needs a domain.
    - **Google sign-in**: **Later, with metis connect google**, or **Now,
      once Metis runs**. This lets people connect Gmail, Google Calendar,
      Drive and Contacts. See
      [Set up Google with the metis CLI](/self-hosting/configure/sign-in-providers#set-up-google-with-the-metis-cli).

    If you use a screen reader, run the script as
    `sudo sh bootstrap.sh --accessible` to get plain prompts instead of the
    form.

  </Step>

  <Step title="Confirm">
    Setup shows a summary under "Install Metis?", for example:

    ```
    Install folder: /opt/metis-suite
    Owner: alice@example.com
    Domain: mail.example.com (Caddy with HTTPS)
    Database: sqld on this server
    Components: updater
    ```

    Answer **Yes** to install. **No** stops with "setup cancelled", and
    nothing is installed.

  </Step>

  <Step title="Wait for it to start">
    Setup prints what it does. It installs Docker if needed ("Docker Engine
    answers"), picks the release ("Using Metis 1.4.0"), downloads the images
    and starts everything. When the app is up, it prints "Metis is running"
    and then:

    - With a domain: "Open https://mail.example.com/setup once DNS for
      mail.example.com points at this server."
    - Without a domain: "Metis listens on 127.0.0.1:3000. Reach it with ssh
      -L 3000:127.0.0.1:3000, then open http://localhost:3000/setup," and
      "or give it a domain with sudo metis domain mail.example.com."
    - **Setup code:** the code that creates the owner account. It is also
      kept as `METIS_SETUP_CODE` in `/opt/metis-suite/.env`.

    Setup creates no DNS record. Point your domain at the server yourself,
    or let `metis domain` create it later on Cloudflare. See
    [Domain and HTTPS](/self-hosting/install/domain-and-https).

  </Step>

  <Step title="Back up the encryption key">
    Setup warns: "Back up METIS_ENCRYPTION_KEY from /opt/metis-suite/.env;
    losing it means reconnecting every mailbox, calendar, drive and address
    book." Copy the key to a safe place, such as a password manager:

    ```bash
    sudo grep METIS_ENCRYPTION_KEY /opt/metis-suite/.env
    ```

    :::warning[Losing this key means reconnecting everything]
    The encryption key protects every password and token users store when
    they connect accounts. Without it, they cannot be read. Every user would
    have to reconnect every mailbox, calendar, drive and address book. Keep
    a copy somewhere other than the server.
    :::

  </Step>

  <Step title="Finish the gateways and Google">
    If you ticked a mail gateway, setup now sets it up ("Setting up
    gateway-resend"). It asks for the **Mail domain**, such as
    `example.com`. The Amazon SES gateway also asks for the **SES region**
    and a **Database URL** and **Database token**. The Amazon SES gateway
    does not ask for AWS credentials. Pass them on the install line, for
    example `sudo AWS_ACCESS_KEY_ID=AKIAIOSFODNN7EXAMPLE AWS_SECRET_ACCESS_KEY=your-secret-access-key sh bootstrap.sh`,
    or add the gateway later with `sudo metis add gateway-ses`, its flags
    and the AWS key on the same line, as
    [Set up the Amazon SES gateway](/self-hosting/mail-gateways/amazon-ses)
    shows.

    If you chose **Now, once Metis runs** for Google sign-in, setup then
    guides you through it ("Connecting Google").

    If one of these fails, Metis Suite still runs. Setup prints why and
    what to run later, for example "gateway-resend was not set up: … Run
    sudo metis add gateway-resend later." or "Google was not connected: …
    Run sudo metis connect google later."

  </Step>

  <Step title="Open the app">
    With a domain, open `/setup` at your domain once DNS points at the
    server, for example `https://mail.example.com/setup`.

    Without a domain, the app listens only on the server itself. Open a
    tunnel from your own computer. Use your own user name and your server's
    address in place of `ana` and `203.0.113.10`:

    ```bash
    ssh -L 3000:127.0.0.1:3000 ana@203.0.113.10
    ```

    Then open `http://localhost:3000/setup` in your browser. Continue with
    [First run](/self-hosting/install/first-run).

  </Step>
</Steps>

## Install without questions

With `--yes`, or when there is no terminal (for example in cloud-init), setup asks nothing and uses the flags. Pass them after `bootstrap.sh`, which hands them to `metis setup`:

```bash
sudo sh bootstrap.sh --yes --owner-email alice@example.com --domain mail.example.com --with updater,worker
```

If a value is missing or wrong, setup stops at once and lists what it needs, for example "setup needs --owner-email you@example.com; --domain mail.example.com".

- **Mail gateways and Google** cannot be set up without questions. Add them once Metis runs, with `sudo metis add` and `sudo metis connect google`.
- **Starting values** for other settings, such as OAuth clients, the AI model, server lists or the workflow runner, go in with `--env` or `--env-file`. They are written to `.env` last, and the first preflight stores them as the starting values of those dashboard settings. See [Environment variables](/self-hosting/reference/environment-variables).

| Flag               | What it does                                                                                                                                                                                              | Default            |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------ |
| `--owner-email`    | The instance owner's email address. Required.                                                                                                                                                             | None               |
| `--domain`         | The hostname people open, such as `mail.example.com`.                                                                                                                                                     | None               |
| `--with`           | The components to add: `updater`, `worker` and `objstore`, separated by commas. The list replaces the default, so `--with worker` installs without the updater. Write `--with updater,worker` to keep it. | `updater`          |
| `--database-url`   | A libSQL database URL to use instead of sqld on this server.                                                                                                                                              | None               |
| `--database-token` | The token for `--database-url`.                                                                                                                                                                           | None               |
| `--version`        | Install this release instead of the newest one this CLI supports, such as `1.4.0`. A leading `v` is ignored.                                                                                              | The newest release |
| `--app-port`       | The port on `127.0.0.1` the app listens on.                                                                                                                                                               | `3000`             |
| `--env`            | An extra `KEY=VALUE` line for `.env`. Repeat it for each line.                                                                                                                                            | None               |
| `--env-file`       | A file of extra `KEY=VALUE` lines for `.env`.                                                                                                                                                             | None               |
| `--dir`            | The install folder. It must be empty, and the path must start with `/`.                                                                                                                                   | `/opt/metis-suite` |
| `--yes`            | Skip the questions and use the flags.                                                                                                                                                                     |                    |

`--with` takes only `updater`, `worker` and `objstore`. A mail gateway there is refused with, for example, "a running install for gateway-resend: add it after setup with metis add gateway-resend".

## Use Turso or your own database server

The app needs two libSQL databases: the app database and the AI memory database. To keep them on [Turso](https://turso.tech) or on a libSQL server (sqld) you run elsewhere, create both first. For Turso, see [Create the databases on Turso](/self-hosting/reference/environment-variables#create-the-databases-on-turso).

In the form, choose **A libSQL database elsewhere (Turso or your own sqld)**, then enter the **App database URL**, the **App database token**, the **Agent memory database URL** and the **Agent memory database token**. URLs start with `libsql://` for Turso, and with `http://`, `https://`, `ws://` or `wss://` for sqld.

Without questions, pass the app database with flags and the memory database with `--env`:

```bash
sudo sh bootstrap.sh --yes --owner-email alice@example.com \
  --database-url libsql://metis-app-acme.turso.io --database-token your-app-database-token \
  --env MASTRA_DATABASE_URL=libsql://metis-memory-acme.turso.io \
  --env MASTRA_DATABASE_AUTH_TOKEN=your-memory-database-token
```

Both URLs must be the same kind: both `libsql://`, or both `http(s)://` or `ws(s)://`.

The server then runs no database server of its own. The updater cannot take a snapshot before an upgrade, so an upgrade cannot be undone. Back up your databases before each upgrade. See [Upgrade and undo](/self-hosting/operate/upgrade-and-undo#snapshots-need-the-database-on-your-server).

## Which release is installed

Setup installs the newest published release that your version of the CLI supports. A release can need a newer CLI. Then:

- Without `--version`, if every release needs a newer CLI, setup stops with, for example, "every published release needs Metis CLI 0.5.0 or later; this is 0.4.0". Download the install script again and run it: it always installs the newest CLI.
- With `--version`, setup stops with, for example, "1.4.0 needs Metis CLI 0.5.0 or later; run sudo metis self-update, then setup again".
- With `--version`, a release that does not exist is refused with a message that starts with, for example, "1.3.9 is not a published release".

The install script always downloads the newest CLI. To install a fixed version of the CLI instead, set `METIS_CLI_VERSION`:

```bash
sudo METIS_CLI_VERSION=0.1.0 sh bootstrap.sh
```

## If the first start fails

The error ends with "Fix the cause, then run sudo metis apply". The install already exists at that point, so running setup again is refused. Fix the cause, then run:

```bash
sudo metis apply
```

## Troubleshooting the install

| Message                                                                                        | What to do                                                                                                                       |
| ---------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| "[bootstrap] run as root: sudo sh bootstrap.sh"                                                | Run the script with `sudo`.                                                                                                      |
| "[bootstrap] unsupported architecture" followed by a name                                      | The server's processor is not amd64 or arm64. Use another server.                                                                |
| "Install Docker Engine first: https://docs.docker.com/engine/install/"                         | The server is not Debian or Ubuntu, so the CLI cannot install Docker. Install Docker Engine yourself, then run the script again. |
| "Docker Engine was installed but does not answer on its socket"                                | Check that the Docker service runs, for example with `sudo systemctl status docker`, then run the script again.                  |
| "/opt/metis-suite is not empty; setup installs only into an empty folder"                      | Choose another folder with `--dir`, or empty this one.                                                                           |
| "Metis is already installed in /opt/metis-suite; use metis status, metis add and metis update" | Metis Suite is installed already. Change it with the other commands. See [CLI commands](/self-hosting/reference/cli-commands).   |
| "setup needs" followed by a list                                                               | Pass the flags it names.                                                                                                         |
| "preflight failed: metis-preflight exited with code 1:" followed by its output                 | A setting is wrong. The output names it. Fix it in `/opt/metis-suite/.env`, then run `sudo metis apply`.                         |
| "metis-sqld was not healthy within 1m0s" followed by its log                                   | The database server did not start. Its log follows the message. Fix the cause, then run `sudo metis apply`.                      |
| "metis-app exited with code 1:" followed by its log                                            | The app stopped. Its log follows the message. Fix the cause, then run `sudo metis apply`.                                        |
