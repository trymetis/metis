---
title: Domain and HTTPS
description: Serve your instance on your own domain with an automatic HTTPS certificate.
---

Until you set a domain, the app listens only on the server itself, at `127.0.0.1:3000`. Without HTTPS, sign-in cookies are not marked secure, so the app is not exposed to the internet. You reach it through an SSH tunnel instead.

Once you set a domain, the `metis` CLI adds Caddy, a web server that gets and renews an HTTPS certificate for you. This page is for a server the `metis` CLI runs. Container platforms and Vercel handle HTTPS themselves.

## Before you start

- Make sure ports 80 and 443 are open on the server and its firewall. Port 443 is used over TCP, and over UDP for HTTP/3.
- Decide on the domain, for example `mail.example.com`. Its DNS record must point at the server. The CLI can create it for you on Cloudflare (see below).

## Set the domain

Run:

```bash
sudo metis domain mail.example.com
```

Write the name only, without `https://`. The command:

1. Changes `BETTER_AUTH_URL` to `https://mail.example.com` in `/opt/metis-suite/.env`.
2. Adds Caddy, which listens on ports 80 and 443.
3. Shows what it changes and restarts the app on the new address.
4. Creates or lists the DNS record (see below).

It ends with "Metis is served on https://mail.example.com once its DNS points at this server". Caddy gets the certificate on the first request, so the first page load can take a few seconds.

You can also set the domain during the install, in the **Domain** field of the form or with `--domain`. Setup creates no DNS record. See [Install with the metis CLI](/self-hosting/install/install-with-bootstrap).

To move to another domain, run the same command with the new name.

### The DNS record

The command finds the server's public IPv4 address. Then:

- **With a Cloudflare API token,** when the domain's zone is on that Cloudflare account, it creates an A record that points the domain at the server, and prints a line such as "DNS A mail.example.com → 203.0.113.10". Pass the token on the same line:

  ```bash
  sudo CLOUDFLARE_API_TOKEN=your-cloudflare-token metis domain mail.example.com
  ```

  The token needs **Zone, Zone: Read** and **Zone, DNS: Edit** for the zone. If the same A record exists, nothing changes. An A record for the same name with another address is not replaced: a second one is added, so delete the old one in Cloudflare yourself.

- **Without a token,** it prints "Add these DNS records at your DNS provider:", followed by the record, such as "A mail.example.com → 203.0.113.10". Add it at your DNS provider.
- **With a token, when the zone is not on that account,** it prints "no zone for mail.example.com is on this Cloudflare account; add the records yourself", followed by the same list.

If the server's address cannot be found, the command prints nothing about DNS. Create the record yourself.

## Remove the domain

```bash
sudo metis domain --remove
```

`BETTER_AUTH_URL` goes back to `http://localhost:3000`, Caddy stops, and the command prints "Metis is reachable on 127.0.0.1 only". Reach the app through an SSH tunnel again. The certificates stay on the server, in the `metis-caddy-data` Docker volume, so they are reused if you set the domain again.

:::warning[Update your OAuth redirect URIs]
The redirect URIs for Google, Microsoft and Zoho are built from your app's address. After you change the domain, open each provider page under **Dashboard**, **System**, copy the new **Redirect URI** and register it in the provider's console. Until you do, connecting those accounts fails. See [OAuth providers](/self-hosting/configure/sign-in-providers).
:::

## Check the result

Open the **Instance** page under **System** in the owner dashboard. The **App** card shows the **Public URL**, and **Secure cookies** reads **Yes** once the address starts with `https://`.

## Behind Cloudflare or another CDN

A CDN (content delivery network) is a service, such as Cloudflare, that sits in front of your server and passes requests on to it. Behind a CDN, requests reach Caddy from the CDN's servers, not from your visitors.

The app uses each visitor's address for rate limits, sign-in limits and the IP addresses in the audit log. If you do nothing, every visitor who comes through one CDN server gets that server's address. They share one rate limit, and the audit log shows the same address for all of them.

If you use Cloudflare, you can fix this. List Cloudflare's address ranges:

1. Copy the IPv4 and IPv6 ranges that Cloudflare lists at [cloudflare.com/ips](https://www.cloudflare.com/ips/).
2. In the owner dashboard, open **System**, then **Instance**.
3. On the **Proxies** card, enter the ranges in **Trusted proxies**, separated by commas. You can enter up to 50.
4. Click **Save changes** and enter a code from your authenticator app.

Caddy puts only the address of the Cloudflare server into `X-Forwarded-For`. Once that address is on your list, the app takes the visitor's address from the `cf-connecting-ip` header that Cloudflare adds.

Another CDN in front of Caddy cannot be fixed this way. Caddy replaces the `X-Forwarded-For` header that the CDN sends with the CDN server's address, and the app reads no other CDN's header. Listing that CDN's ranges changes nothing. Visitors still share the CDN server's address for rate limits and in the audit log.

With Cloudflare, if your workflows use webhooks with **Only from these IPs**, list the same ranges in **Trusted proxies** on the **Workflow runner** page too. That list is separate. See [Webhooks that only accept some addresses](/self-hosting/configure/background-work#webhooks-that-only-accept-some-addresses).

List only Cloudflare's published ranges. A list that is too wide, such as `0.0.0.0/0`, lets a caller choose their own address. See [Proxies](/self-hosting/reference/dashboard-settings#proxies) for the full rules.

:::note
Without a CDN, Caddy alone needs nothing in this list.
:::

## If something goes wrong

| Message                                                                                                          | What to do                                                                                                                                                                                      |
| ---------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| "enter a hostname such as mail.example.com, without https://"                                                    | Write the domain name only, such as `mail.example.com`.                                                                                                                                         |
| "metis domain changes the server; run it as root: sudo metis domain mail.example.com"                            | Run the command with `sudo`.                                                                                                                                                                    |
| "objstore --direct serves files from a public host on the domain; run metis add objstore without --direct first" | Object storage serves files on your domain. Run `sudo metis add objstore` first, then remove the domain. See [Drive transfers](/self-hosting/configure/drive-transfers#storage-on-your-server). |
| "the Resend gateway needs a public HTTPS address; run metis remove gateway-resend first"                         | Remove the Resend gateway first. See [Set up the Resend gateway](/self-hosting/mail-gateways/resend).                                                                                           |
| "Caddy comes with a domain: run metis domain mail.example.com"                                                   | You ran `metis add caddy`. Set a domain instead.                                                                                                                                                |
| "Caddy goes with the domain: run metis domain --remove"                                                          | You ran `metis remove caddy`. Remove the domain instead.                                                                                                                                        |

If the certificate never arrives, check that DNS points at this server and that ports 80 and 443 are reachable from the internet. Caddy's log shows what failed:

```bash
sudo metis logs caddy
```
