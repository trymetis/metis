AI is off on a new instance. Metis Suite does not include a model: you bring your own, from OpenAI, Anthropic, or any service with an OpenAI-compatible API, including one you run yourself.

While AI is off, the assistant, smart replies, AI labels, thread summaries and the MCP server are unavailable. People on your instance can also turn AI off for their own workspaces and mailboxes; those switches cover every model call.

## Set up the LLM

Open **Dashboard**, **System**, **LLM** under **Drivers**.

| Field                     | What to enter                                                                      |
| ------------------------- | ---------------------------------------------------------------------------------- |
| **Driver**                | `openai`, `anthropic`, `openai-compatible`, or `disabled` to turn AI off.          |
| **API key**               | Your provider's key. Optional only for `openai-compatible`.                        |
| **Base URL**              | `openai-compatible` only: the address of the API.                                  |
| **Provider name**         | `openai-compatible` only, optional: a name for the provider.                       |
| **Structured outputs**    | `openai-compatible` only. Turn it on if your provider supports structured outputs. |
| **Chat and agents model** | The model for the assistant and agents.                                            |
| **Smart replies model**   | The model for suggested replies.                                                   |
| **Classifier model**      | The model that sorts mail into labels.                                             |
| **Summaries model**       | The model for thread summaries.                                                    |
| **Images in summaries**   | Sends the images in a message to the summaries model too. Off by default.          |

All four model fields are required when a driver is on. Enter the model names your provider uses. You can use the same model for all four.

Without structured outputs, summaries need a model with a context window of about 8k tokens or more.

Click **Save changes** and enter your authenticator code. Saving a change to these fields checks the LLM before anything is stored: it lists your provider's models with your key and confirms that every model you entered is offered. If the check fails, for example with "the API key was rejected (401)", nothing is saved. A model that is "not in the provider's model list" does not stop the save. The save does not show this warning. Click **Run check** to see it.

Then click **Run check** in the **Health** card. It runs the same check without saving and shows every result. If it reports "the API key was rejected (401)" or "not in the provider's model list", fix the key or the model name.

Every deploy runs the same check while the LLM **Driver** is not `disabled`. Problems appear on the **Deploy checks** page of the dashboard, in the **LLM** group. A problem there never stops the deploy. See [Troubleshooting](/self-hosting/operate/troubleshooting#read-the-deploy-checks).

You can also set the starting values before the first start:

```bash
METIS_LLM_DRIVER=openai
OPENAI_API_KEY=<key>
METIS_LLM_CHAT_MODEL=<model>
METIS_LLM_SMART_REPLY_MODEL=<model>
METIS_LLM_CLASSIFIER_MODEL=<model>
METIS_LLM_SUMMARY_MODEL=<model>
```

Use `ANTHROPIC_API_KEY` for `anthropic`. For `openai-compatible`, use `METIS_LLM_BASE_URL`, `METIS_LLM_API_KEY` and, optionally, `METIS_LLM_NAME` and `METIS_LLM_STRUCTURED_OUTPUTS`.

### Where to get a key

| Provider   | **Driver**          | **API key**                                                                                                                             | **Base URL**                    |
| ---------- | ------------------- | --------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------- |
| OpenAI     | `openai`            | Create one on OpenAI's [API keys page](https://platform.openai.com/settings/organization/api-keys).                                     | Not used.                       |
| Anthropic  | `anthropic`         | In the Claude Console, open [API keys](https://platform.claude.com/settings/keys) and click **Create key**. The key is shown only once. | Not used.                       |
| OpenRouter | `openai-compatible` | Create one on OpenRouter's [keys page](https://openrouter.ai/keys).                                                                     | `https://openrouter.ai/api/v1`  |
| Ollama     | `openai-compatible` | Leave it empty. Ollama ignores the key.                                                                                                 | `http://<ollama host>:11434/v1` |

For Ollama, use an address your Metis Suite server can reach. Ollama's own guide uses `http://localhost:11434/v1`, the address on the machine where Ollama runs. See the guides from [OpenAI](https://developers.openai.com/api/docs/quickstart), [Anthropic](https://platform.claude.com/docs/en/get-api-key), [OpenRouter](https://openrouter.ai/docs/quickstart) and [Ollama](https://docs.ollama.com/api/openai-compatibility).

### What the models need

- **Structured output.** Inbox labels, summaries, smart replies and workflow AI steps ask the model for answers in a fixed format. With `openai-compatible` and **Structured outputs** off, the endpoint gets JSON mode and the format is written into the prompt. Turn **Structured outputs** on only if your endpoint supports JSON schema output.
- **Tools.** The assistant and agents call tools, so choose a **Chat and agents model** that supports tool calling.
- **Images.** With **Images in summaries** on, the summaries model must accept images.
- **OpenRouter.** Support for structured outputs and tools varies by model. OpenRouter's models list can show only the models with [structured outputs](https://openrouter.ai/models?supported_parameters=structured_outputs) or with [tool calling](https://openrouter.ai/models?supported_parameters=tools). See OpenRouter's [structured outputs](https://openrouter.ai/docs/features/structured-outputs) and [tool calling](https://openrouter.ai/docs/guides/features/tool-calling) guides.
- **Ollama.** Ollama supports JSON mode and structured outputs through its OpenAI-compatible API. Ollama's cloud does not support structured outputs. See Ollama's [structured outputs](https://docs.ollama.com/capabilities/structured-outputs) guide.

The **AI usage** page of the dashboard shows the tokens every feature uses. See [Owner dashboard](/self-hosting/operate/owner-dashboard).

## Add a decision model (optional)

A decision model is a second, optional AI backend. It answers typed questions about a message, such as yes or no, pick one, or a rating, with probabilities, in one call. It writes no text. It adds to the LLM and never replaces it.

You set it up on the same **LLM** page, in the **Decision model** card.

| Field        | What to enter                                                                                            |
| ------------ | -------------------------------------------------------------------------------------------------------- |
| **Driver**   | `systemone`, `openai` or `disabled` (the default).                                                       |
| **Model**    | The model name. Required unless the driver is disabled.                                                  |
| **Base URL** | `systemone` only, optional. The server's address.                                                        |
| **API key**  | Required for `openai`. Optional for `systemone`, but a server that checks keys rejects calls without it. |

**Model** has no default. Type the model name exactly as your provider names it.

- **`systemone`:** **Base URL** defaults to `https://api.typesafe.ai/v1`, TypeSafe's hosted service. You can point it at any other server that implements TypeSafe's SystemOne API (`POST /systemone`). Without an API key, every deploy warns that a server that checks keys will reject every decision call.
- **`openai`:** Metis Suite sends the model name you type to OpenAI's own API. Enter a decision model name that your OpenAI account offers. This driver has no **Base URL**. Enter your OpenAI API key in the card's **API key** field. Changing the key on the LLM card does not change it.

A driver alone turns nothing on. Each feature has its own switch in the card, all off by default:

| Switch                      | What it does                                                      |
| --------------------------- | ----------------------------------------------------------------- |
| **Inbox labels**            | Uses the decision model to label incoming mail.                   |
| **Summary gate**            | Uses the decision model as a gate for thread summaries.           |
| **Workflow Ask and Branch** | Uses the decision model in the Ask and Branch steps of workflows. |

**Inbox label calls at a time** (1 to 25, default 5) sets how many inbox label calls run at the same time.

The card's badge shows **Off** while the driver is `disabled`, **Configured** when a driver is set but every switch is off, and **On** when at least one switch is on.

Click **Save changes** and enter your authenticator code. The decision model is checked against its server before anything is stored. **Run check** in the **Health** card checks it too.

:::warning
A decision switch does nothing while the LLM driver is `disabled`, because AI is off for the whole instance. The dashboard refuses to save a change that leaves a decision switch on without an LLM. Set up an LLM first, or turn the switch off.
:::

You can also set the starting values before the first start, with the `METIS_DECISION_*` variables. See [Environment variables](/self-hosting/reference/environment-variables#decision-model).

## What leaves your instance

AI features send the parts of a message they need to your provider: the sender, the subject, a snippet, and the body only where a feature needs it. They send nothing for mailboxes whose AI switch is off in that workspace. The decision model receives the same fields.
