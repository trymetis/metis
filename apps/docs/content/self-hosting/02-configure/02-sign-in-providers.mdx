---
title: OAuth providers
description: Create OAuth clients for Google, Microsoft and Zoho so users can connect Gmail, Outlook, Zoho Mail and their calendars, drives and contacts.
---

People sign in to Metis Suite with their email and password, or with a magic link, and then with two-factor authentication. Google, Microsoft and Zoho play no part in that sign-in. This page sets up those providers for one job only: letting users connect their mail, calendars, drives and contacts.

Users connect Google, Microsoft and Zoho accounts by signing in to the provider and giving Metis Suite permission. For that, your instance needs its own OAuth client (an app registration) at each provider you want to offer. Only providers you configure appear in the connect dialog.

| Provider  | What users can connect                                   |
| --------- | -------------------------------------------------------- |
| Google    | Gmail, Google Calendar, Google Drive and Google Contacts |
| Microsoft | Outlook, Outlook Calendar, OneDrive and Outlook Contacts |
| Zoho      | Zoho Mail, Zoho Calendar and Zoho Contacts               |

## Find your redirect URI

Each provider needs to know where to send users back after they sign in. Open **Dashboard**, **System**, then the provider's page under **Providers**. The **OAuth client** card shows the **Redirect URI**. Register it in the provider's console exactly as shown.

The redirect URI has this form, with your app's address at the start:

```
https://mail.example.com/api/connections/google/callback
https://mail.example.com/api/connections/microsoft/callback
https://mail.example.com/api/connections/zoho/callback
```

## Create the OAuth client

<Tabs>
  <Tab title="Google">
    In the Google Cloud console, create a project or pick an existing one.
    Then:

    1. Enable the [Gmail API](https://console.cloud.google.com/apis/enableflow;apiid=gmail.googleapis.com),
       the [Google Calendar API](https://console.cloud.google.com/apis/enableflow;apiid=calendar-json.googleapis.com),
       the [Google Drive API](https://console.cloud.google.com/apis/enableflow;apiid=drive.googleapis.com)
       and the [People API](https://console.cloud.google.com/apis/enableflow;apiid=people.googleapis.com).
       Google Contacts works through the People API.
       With the gcloud CLI, you can run
       `gcloud services enable gmail.googleapis.com calendar-json.googleapis.com drive.googleapis.com people.googleapis.com`
       instead.
    2. Open [Google Auth platform](https://console.developers.google.com/auth/overview).
       If it says "Google Auth platform not configured yet", click
       **Get Started**. Enter an **App name** and a **User support email**,
       choose the audience (**External** or **Internal**), enter a contact
       email address, agree to the Google API Services User Data Policy,
       and click **Create**.
    3. Under [Data Access](https://console.developers.google.com/auth/scopes),
       click **Add or Remove Scopes**, add the permissions listed below, and
       click **Save**. The page then lists which of them are sensitive and
       which are restricted.
    4. Under **Clients**, click **Create Client**. Set **Application type**
       to **Web application** and enter a **Name**. Under
       **Authorized redirect URIs**, click **Add URI** and paste your
       redirect URI. Click **Create**.
    5. Copy the client ID and the client secret. Google shows the full
       secret only once, when you create the client. After that, the
       console shows only its last four characters.

    Metis Suite asks users for these permissions, depending on what they
    connect: `openid`, `email` and `profile`; `gmail.modify` and `gmail.send`
    for mail; `calendar` for calendars; `drive` for drives;
    `https://www.googleapis.com/auth/contacts` for contacts.

    **Who can connect.** Choose the audience under
    [Audience](https://console.developers.google.com/auth/audience):

    - **Internal:** only members of your Google Cloud organization.
    - **External**, in **Testing**: only the test users you add under
      **Test users**, at most 100. Google ends a test user's access seven
      days after they give it.
    - **External**, in production: any Google account, after you click
      **Publish app**.

    **Google verification.** `gmail.modify` and `drive` are restricted
    scopes. An app that is in production and open to everyone needs
    Google's verification for them, including a security assessment by an
    assessor Google approves, repeated at least every 12 months. Google
    makes exceptions for personal use by a few people you know, for an
    internal app, and for apps in testing. See Google's guide to
    [restricted scope verification](https://developers.google.com/identity/protocols/oauth2/production-readiness/restricted-scope-verification).

    The `contacts` scope is a sensitive scope. A public app in production
    needs Google's verification for it too, but no security assessment.
    See Google's guide to
    [sensitive scope verification](https://developers.google.com/identity/protocols/oauth2/production-readiness/sensitive-scope-verification).

    Google's own guides: [configure the consent screen](https://developers.google.com/workspace/guides/configure-oauth-consent),
    [create a client](https://developers.google.com/workspace/guides/create-credentials)
    and [manage the audience](https://support.google.com/cloud/answer/15549945).

  </Tab>
  <Tab title="Microsoft">
    In the [Microsoft Entra admin center](https://entra.microsoft.com):

    1. Open **Entra ID**, **App registrations**, and click
       **New registration**. Enter a **Name**. You need at least the
       Application Developer role.
    2. Under **Supported account types**, choose
       **Any Entra ID Tenant + Personal Microsoft accounts**. Older screens
       call it "Accounts in any organizational directory (Any Microsoft
       Entra directory - Multitenant) and personal Microsoft accounts (such
       as Skype, Xbox)". Its
       `signInAudience` value is `AzureADandPersonalMicrosoftAccount`.
       Metis Suite connects accounts through Microsoft's common endpoint,
       which serves both work and personal accounts. Click **Register**.
    3. Copy the **Application (client) ID** from the **Overview** page.
    4. Under **Authentication**, open the **Redirect URI configuration**
       tab and click **Add Redirect URI**. Choose **Web**, enter your
       redirect URI under **Redirect URI**, and click **Configure**.
    5. Under **Certificates & secrets**, **Client secrets**, click
       **New client secret**. Choose an expiry of at most 24 months, then
       click **Add**. Copy the **Value** right away: Microsoft never shows
       it again after you leave the page. Before it expires, create a new
       secret and enter it in the dashboard.

    Metis Suite asks users for these Microsoft Graph permissions, depending
    on what they connect: `openid`, `email`, `profile`, `User.Read` and
    `offline_access`; `Mail.ReadWrite` and `Mail.Send` for mail;
    `Calendars.ReadWrite` for calendars; `Files.ReadWrite` for drives;
    `Contacts.ReadWrite` for contacts.

    **Admin consent.** Users give these permissions when they connect,
    unless an admin of their organization has already consented. To
    consent for a whole organization, add the permissions under
    **API permissions**, **Add a permission**, **Microsoft Graph**,
    **Delegated permissions**. An admin can then click
    **Grant admin consent for**, followed by the name of the organization.

    **Publisher verification.** Microsoft can block users in other
    organizations from consenting to a multitenant app whose publisher is
    not verified. They see an unverified publisher warning. Verification
    is free. It needs a Microsoft AI Cloud Partner Program account and a
    domain of your own, not `*.onmicrosoft.com`. An app registered with a
    personal Microsoft account cannot be verified. See Microsoft's guide to
    [publisher verification](https://learn.microsoft.com/en-us/entra/identity-platform/publisher-verification-overview).

    Microsoft's own guides: [register an app](https://learn.microsoft.com/en-us/entra/identity-platform/quickstart-register-app),
    [add a redirect URI](https://learn.microsoft.com/en-us/entra/identity-platform/how-to-add-redirect-uri)
    and [add a client secret](https://learn.microsoft.com/en-us/entra/identity-platform/how-to-add-credentials).

  </Tab>
  <Tab title="Zoho">
    Use the Zoho API console of the data center your users' Zoho accounts
    live in:

    | **Region** in Metis Suite | API console                                         |
    | ------------------------- | --------------------------------------------------- |
    | `com` (the default)       | [api-console.zoho.com](https://api-console.zoho.com) |
    | `eu`                      | [api-console.zoho.eu](https://api-console.zoho.eu)   |
    | `in`                      | [api-console.zoho.in](https://api-console.zoho.in)   |
    | `com.au`                  | [api-console.zoho.com.au](https://api-console.zoho.com.au) |
    | `jp`                      | [api-console.zoho.jp](https://api-console.zoho.jp)   |

    1. Click **GET STARTED**, or **ADD CLIENT** if you already have
       clients. Hover over **Server-based Applications** and click
       **CREATE NOW**.
    2. Enter a **Client Name**, your app's address as the **Homepage URL**,
       and your redirect URI under **Authorized Redirect URIs**. Click
       **CREATE**.
    3. Copy the client ID and the client secret from the **Client Secret**
       tab.

    Metis Suite asks users for `AaaServer.profile.READ`; `ZohoMail.messages.ALL`,
    `ZohoMail.folders.ALL` and `ZohoMail.accounts.READ` for mail;
    `ZohoCalendar.calendar.ALL` and `ZohoCalendar.event.ALL` for calendars;
    and `ZohoContacts.contactapi.ALL` for contacts.

    Zoho's own guide: [set up an OAuth client](https://www.zoho.com/accounts/protocol/oauth-setup.html).

  </Tab>
</Tabs>

## Add the client to Metis Suite

1. Open **Dashboard**, **System**, then the provider under **Providers**.
2. Enter the **Client ID** and **Client secret**. For Zoho, also pick the **Region**.
3. Click **Save changes** and enter your authenticator code. The client is checked before it is saved. If the check fails, fix the fields and save again, or click **Save anyway**. See [Save anyway](/self-hosting/configure/how-configuration-works#save-anyway).
4. In the **Health** card, click **Run check**. It confirms the provider accepts your client ID and secret.

You can also set the starting values before the first start, with `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`, `MICROSOFT_CLIENT_ID` and `MICROSOFT_CLIENT_SECRET`, or `ZOHO_CLIENT_ID`, `ZOHO_CLIENT_SECRET` and `ZOHO_REGION`. After the first start, change them in the dashboard.

:::warning[Removing a provider hides its accounts]
If you clear a provider's client, every account connected through it is quarantined: it disappears from every workspace. The accounts come back when you configure the provider again. Users can also delete them from their account settings. If a reset to the environment would clear a provider that accounts use, the reset's dialog lists the provider, and you must tick **Reset anyway and quarantine these connections** first.
:::

:::note
The redirect URI changes when your app's address changes. After you move to a new domain, register the new redirect URI with each provider.
:::

## Set up Google with the metis CLI

The `metis` CLI can guide you through the Google OAuth client and store it for you. Google does not let anyone create an OAuth client through its API, so you still make the consent screen and the client in the Google Cloud console yourself. The CLI shows a link to each page and checks the result.

On a server the `metis` CLI runs:

```bash
sudo metis connect google
```

Away from the server, for a container platform or Vercel, run it on your own computer with the deployment's environment file and release. See [Change settings away from the server](/self-hosting/configure/how-configuration-works#change-settings-away-from-the-server).

```bash
metis connect google --env-file production.env --version 1.2.3
```

The redirect URI comes from `BETTER_AUTH_URL` in `.env` or in the file, for example `https://mail.example.com/api/connections/google/callback`. Set your domain first. See [Domain and HTTPS](/self-hosting/install/domain-and-https).

<Steps>
  <Step title="Pick the project">
    If the `gcloud` CLI is signed in on the machine, the CLI asks for the
    **Project ID**: "gcloud is signed in. Leave this blank to create a new
    project." Leave it blank, and it creates a project named Metis, with an
    id such as `metis-abcdef`, and prints "Created the project
    metis-abcdef". It then turns on the APIs Metis Suite needs and prints
    "Turned on the Gmail, Calendar, Drive and People APIs".

    Otherwise, it prints a link to create a project, and a link for each
    API to turn on: `gmail.googleapis.com`,
    `calendar-json.googleapis.com`, `drive.googleapis.com` and
    `people.googleapis.com`. Turn them on, then enter the **Project ID**.

    On a server, `sudo` runs `gcloud` as root, so it counts as signed in
    only if root's `gcloud` is.

  </Step>

  <Step title="Follow the four screens">
    The CLI shows four screens, each with a link to the right page of your
    project in the Google Cloud console:

    1. **Branding**: "Set the app name (Metis) and a support email."
    2. **Audience**: with Google Workspace, choose **Internal**. Otherwise
       choose **External**, then **Publish app**. People then see Google's
       "unverified app" screen before they consent, and the project can
       sign up at most 100 new users over its lifetime. Leave **Testing**
       alone: its tokens expire after 7 days.
    3. **Data access**: add the scopes it lists:
       `https://www.googleapis.com/auth/gmail.modify`,
       `https://www.googleapis.com/auth/gmail.send`,
       `https://www.googleapis.com/auth/calendar`,
       `https://www.googleapis.com/auth/drive` and
       `https://www.googleapis.com/auth/contacts`.
    4. **Client**: "Choose Web application and add this authorised redirect
       URI:" followed by your redirect URI.

  </Step>

  <Step title="Enter the client ID and secret">
    Paste the **Client ID**, which ends in `.apps.googleusercontent.com`,
    and the **Client secret**. The CLI checks the pair with Google. When
    Google accepts it, it prints "Google accepts the client".

  </Step>

  <Step title="Let it store the client">
    The CLI stores the client as `metis config set` does with
    `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`. On a server, it writes
    them to `.env` and stores the **Google** card in the database, which
    **History** shows as a **Server** version. Away from the server, it
    updates your file and stores them through the release's preflight
    image. See
    [Change dashboard settings with the metis CLI](/self-hosting/configure/how-configuration-works#change-dashboard-settings-with-the-metis-cli).

  </Step>
</Steps>

If you already have a client, skip the guided screens:

```bash
sudo metis connect google --client-id 1234-abc.apps.googleusercontent.com --client-secret your-client-secret
```

| Flag              | What it does                                             |
| ----------------- | -------------------------------------------------------- |
| `--client-id`     | An existing client ID, skipping the guided steps.        |
| `--client-secret` | The secret for `--client-id`.                            |
| `--project`       | The Google Cloud project to use.                         |
| `--env-file`      | Away from the server: the deployment's environment file. |
| `--version`       | With `--env-file`: the release the deployment runs.      |
| `--yes`           | Go ahead without asking.                                 |

| Message                                                                                          | What to do                                                         |
| ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------ |
| "Google does not accept this client ID and secret"                                               | Copy the client ID and secret again from the Google Cloud console. |
| "without a terminal, pass --client-id and --client-secret"                                       | Run it in a terminal, or pass both flags.                          |
| "away from the server, pass --env-file FILE: the deployment's environment, with BETTER_AUTH_URL" | Pass `--env-file` with your deployment's environment file.         |
| "production.env sets no BETTER_AUTH_URL"                                                         | Add `BETTER_AUTH_URL` to the file.                                 |

## Add contacts to a provider you already use

If your OAuth client does not include the contacts permission yet, update it in the provider's console, as listed above:

- **Google:** enable the People API, and add `https://www.googleapis.com/auth/contacts` under **Data Access**.
- **Microsoft:** add `Contacts.ReadWrite` if you list the permissions under **API permissions** for admin consent.
- **Zoho:** nothing changes in the API console. Metis Suite asks for `ZohoContacts.contactapi.ALL` when a user connects.

Accounts that are already connected keep working. They ask for the new permission the first time someone adds the account's address book.
